# Кора-агент: план перехода (27.09.2026)

Зачем. Живые тесты 27.09 показали: у разговора два хозяина. Автомат в `src/core/host.js` ведёт очередь по таймерам и регуляркам (закрывашки, «всё?» через 2,5 с, адресация «к ней ли это» по словам), а мозг-LLM вызывается, только когда автомат решил, и его ответ режут фильтры по поводу вызова. Каждый новый вариант разговора ломает стык между ними, и каждая починка добавляет ещё одно правило. Решение владельца: **агент на инструментах вместо промпта с одним JSON-действием и кода-автомата**; паузы на обдумывание закрывать промежуточными словами.

## Принцип

- **Что сказать — решает только агент** (LLM с инструментами): отвечать, молчать, спросить «всё?», поблагодарить и передать слово, спросить «кто хочет добавить?», попрощаться.
- **Когда можно говорить и что недопустимо — решает код**: пропуск на реплику (тишина, эхо, перебивание), стоп-фразы, дедлайны, бюджеты, пустая комната, защита от повторов и устаревших реплик, очистка текста.
- Новый провал в живом тесте превращается в **сценарий** (`src/agent/scenarios.js`), а не в регулярку в хосте.

## Устройство

```
слоты Телемоста ─► уши (SpeechKit STT на слот) ─► фраза: промежуточный текст / финал
                    └► Smart Turn v3 (звук) ─────► p(фраза закончена)
подсветка плиток / метаданные Телемоста ─► кто говорит (или «?», если не уверены)
                                     │
                          события ───┴──► хост-агент ─► политика пробуждения ─► агент (LLM + инструменты)
                                                                                     │ вызовы инструментов
                              очередь речи ◄──── исполнитель действий ◄──────────────┘
                              (готовые клипы / живой синтез, промежуточные слова)
                                     │
                              пропуск на реплику (floor), перебивание ─► плеер страницы
```

### События агенту

`heard {who, text, complete?, partial?}` · `silence {ms, after}` · `joined / left {who}` · `her_line_done {text, cut?}` · `interrupted {text}` · `chorus {who}`. Состояние в каждом запросе: `phase`, `speaker`, `queue`, `present`, `dialog` (последние реплики, её — с `who: "host"`).

### Инструменты агента

| инструмент | что делает код |
|---|---|
| `say(text)` | очистка текста → очередь речи; фраза из `phrases.json` играет готовым клипом |
| `give_word(person_id, text)` | пустой `text` → клипы «Спасибо, X!» + «Дальше Y»; свой `text` — живой синтез; меняет `speaker`/`queue` |
| `ask_done(person_id)` | клип «X, всё?» |
| `skip()` | ничего |
| `leave(text)` | прощание → выход |

Состояние очереди (`speaker`, `queue`, `phase`) хранит код и меняет только по вызовам инструментов и по фактам (ушёл, пришёл). Агент видит его в каждом запросе.

### Политика пробуждения (код)

Агент зовётся не на каждый чих, а на события, после которых возможно решение:

- финал фразы; или промежуточная гипотеза, когда Smart Turn говорит «закончил» (`p ≥ T`, см. [smart_turn_plan.md](smart_turn_plan.md));
- тишина: ≥ 1 с после законченной фразы, ≥ 4 с после незаконченной;
- пришёл / ушёл, её реплику перебили, её реплика закончилась в круге;
- в очереди максимум один запрос в полёте и один ожидающий (новый заменяет ожидающий); новое событие по той же теме делает ждущие реплики устаревшими (механизм `superseded` из `host.js`).

### Промежуточные слова

Имя инструмента приходит в стриме раньше аргументов (`src/brain/tool_stream.js`, `onToolName`). Если выбран `say` / `give_word` со своим текстом, а синтез реплики не успевает за ~250 мс, играет короткий готовый клип («Так…», «Угу», «Секунду», «Хм»): ротация, не чаще одного на реплику, никогда перед `skip` и перед готовыми клипами.

### Скиллы

Плейбук режется на блоки по фазам (ожидание, круг, открытое слово, прощание, вопросы о себе); в запрос идёт общий блок + блок текущей фазы. Цель — промпт ≤ 3k токенов вместо ~7k: AI Studio не кэширует промпт, длина = задержка и деньги.

## Риски и что делаем

- **AI Studio не умеет вызов инструментов для модели** (шаг 0). Хост-агент не зависит от формата: адаптер агента возвращает список действий. Запасной формат — JSON-массив действий в ответе (тот же `completedFields` для раннего имени действия).
- **Задержка одного вызова ~1,1 с при промпте 7k.** Скиллы (шаг 5), промежуточные слова (шаг 6), Smart Turn (шаг 7). Цель: первый звук ≤ 1 с после конца фразы, ответ ≤ 1,5 с.
- **Цена: вызов на каждую фразу.** Оценка на стендап 6 человек / 30 мин: ~150–250 вызовов × 3k токенов ≈ 0,5–0,8 млн входных токенов. Тариф `aliceai-llm-flash` сверить; AI Studio стоимость не отдаёт, считать по токенам в `cost.summary`.
- **Модель ошибается в «к ней ли это»** (MP-Bench: без имени — около случайного). Правило в промпте и сценариях: без имени в группе отвечать только при явном «ты» к ней / продолжении её же разговора; точные подписи спикеров (шаг 0, метаданные Телемоста) важнее, чем промпт.
- **Кто говорит — «?», когда подсвечены двое и громкость не помогает** (приём Vexa): агенту лучше видеть «?», чем чужое имя.

## Открытые вопросы

- Есть ли в сигнальном канале Телемоста id говорящего (шаг 0) — тогда атрибуция по подсветке станет запасной.
- Нужно ли агенту менять очередь явно (`set_queue`) или хватает `give_word` + порядок из ростера.
- Где живёт код: хост-агент — новый файл; общие части (очередь речи, пропуск на реплику, эхо) выносятся из `host.js` по мере надобности, а не заранее.
