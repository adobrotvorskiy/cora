# Smart Turn v3: план (27.09.2026, ред. под хост-агента)

Цель — сократить задержку ответа (~2 с по замерам 27.09) и отличать «человек закончил» от «человек задумался посреди фразы». Обзор, откуда взялась модель, — в [opensource_group_voice.md](opensource_group_voice.md); общий план перехода на агента — в [agent_plan.md](agent_plan.md).

## Модель

[pipecat-ai/smart-turn](https://github.com/pipecat-ai/smart-turn), версия 3.2, лицензия BSD-2-Clause.

- Смотрит на **звук**, а не на текст: интонацию, темп, обрыв слова.
- Выдаёт вероятность того, что реплика закончена; порог в примере — 0,5.
- Внутри Whisper Tiny + линейный классификатор, ~8 млн параметров. 23 языка, русский есть.
- Два файла ONNX: int8 для CPU на 8 МБ и fp32 для GPU на 32 МБ. На CPU 10–100 мс.
- Вход — последние ≤8 с текущей реплики, 16 кГц моно. Если звука меньше 8 с, нули добавляются **в начало**. Запускать её надо, когда VAD увидел тишину; если человек заговорил снова, прогнать заново по всей реплике.

### Нужно ли что-то разворачивать

Нет, сервер и GPU не нужны. Модель работает в нашем Node-процессе на CPU ноутбука:

- **Рантайм** — npm-пакет `onnxruntime-node` с готовыми бинарниками для macOS, Linux и Windows.
- **Веса** — один файл на 8 МБ. В git не кладём: скрипт скачивает его в `models/` (в `.gitignore`) и сверяет sha256.
- **Признаки** — log-mel как у `WhisperFeatureExtractor(chunk_length=8)` из `inference.py` репозитория. Это около 100 строк JS:
  - обрезка или дополнение нулями слева до 128 000 отсчётов;
  - нормировка к нулевому среднему и единичной дисперсии (`do_normalize=True`);
  - STFT с n_fft 400, hop 160 и окном Ханна;
  - 80 мел-фильтров Slaney;
  - `log10`, ограничение снизу на уровне `max - 8`, затем `(x + 4) / 4`.

  На выходе тензор `input_features` [1, 80, 800]. `@huggingface/transformers` ради этого не тянем: он тащит `sharp` и лишний рантайм.

Остальное из обзора разворачивать не нужно или не стоит:

- LiveKit turn-detector тоже локальный (281 МБ), но с лицензией под LiveKit;
- When2Speak — это данные, а не сервис;
- SAA — только облако.

## Как применяем (ред. 27.09, после обсуждения с владельцем)

Первая версия плана (соседняя сессия) закрывала поток SpeechKit раньше времени и встраивала модель в `host.js` / `floor.js`. Изменено, потому что каскадный хост уходит под хост-агента ([agent_plan.md](agent_plan.md)), а раннее закрытие потока — ставка на неизвестную величину:

- **Не закрываем поток SpeechKit раньше.** Выигрыш зависел от того, как быстро приходит финал после закрытия потока (не измерено), а ложное «закончил» резало фразу надвое. Вместо этого агента будят по **последней промежуточной гипотезе**, которая уже есть бесплатно (`stt_delta.so_far`), как только модель сказала «закончил». Финал приходит как обычно и уточняет текст.
- **Порог подбираем на живой записи, а не на синтезе.** SpeechKit TTS произносит оборванную фразу с законченной интонацией, настоящей заминки в нём нет — порог по синтезу соврёт. Синтез остаётся только как проверка конвейера.
- **Подключаем в хост-агента, а не в `host.js`.** Модель решает, *когда будить* агента; вероятность уходит агенту в событии; что делать (ждать, «всё?», отвечать) решает агент. В `floor.js` и `host.js` правок нет.

### Уши: подсказка по каждой фразе

В `yandex_ears.js` у сессии слота кольцевой буфер текущей фразы (≤ 8 с, 16 кГц; ресэмпл 24→16 кГц уже есть). На **первом тихом чанке** слота (~100 мс после конца речи) — прогон модели. Энергия чанка — той же мерой, что в ворклете. Уши шлют событие

`turn_hint {track_id, p, ms, so_far, t}` — `so_far` = последняя промежуточная гипотеза этой фразы.

Если слот заговорил снова, следующий тихий чанк даёт новый прогон по всей фразе. Пустая гипотеза — подсказка уходит, но будить по ней нечего.

### Хост-агент: политика пробуждения

- `p ≥ T_wake` и непустой `so_far` → будим агента сразу: `heard {who, text: so_far, partial: true, complete: p}`.
- Финал: если он продолжает / совпадает с тем, по чему уже будили, — агент не зовётся повторно; если текст заметно другой (новые слова после `so_far`) — новое пробуждение, ждущие реплики становятся устаревшими (`superseded`).
- Слот заговорил снова после раннего пробуждения → ждущая реплика по первой половине выбрасывается; если она уже звучит — её перебьёт распознанная речь продолжения (`interruptsHost`), как сейчас.
- `p < T_wake`: модель прогоняется ещё раз на 0,5 / 1 / 2 с тишины с убывающим порогом (задумавшийся либо продолжит, либо тишина сама станет ответом); иначе будим на финале с `complete: p`, а тишина после «незаконченной» будит по обычной лестнице (2,5 с), а не через 4 с — иначе каждый ложный «не закончил» стоит 1,5 с.
- «Совпадает» определяется формально: слова финала начинаются со слов `so_far` или сходство по словам (Jaccard) ≥ 0,8. Если совпадения по оценке (шаг 3) бывает меньше чем в 80% фраз — будим не по первой гипотезе на тихом чанке, а по следующей, ждём её ≤ 300 мс.

`T_wake` подбирается на записи (шаг 2): цена ложного «закончил» — лишний вызов агента и, изредка, ответ на полвопроса, который тут же отменяется.

## Шаги

Каждый шаг — отдельный коммит с тестами, `npm test` остаётся герметичным.

1. **Запись слотов (общий шаг с настройкой распознавания).** Флаг `--record` у `tools/run_testroom.js`: PCM каждого слота (16 кГц, то, что уходит в SpeechKit) + события фраз (`stt_delta`, `stt_final` с временами) в `_internal/rec_<время>/` (в `.gitignore`). Запись — только в тест-комнате и только с согласия владельца.
   - **Сценарий чтения** (`tools/record_turns.js` показывает фразы в консоли по одной): ~20 законченных («вчера закрыл два бага, сегодня на ревью», «у меня всё») и ~20 оборванных («сегодня я доделываю интеграцию с…», «вчера я занимался, э-э…» + пауза 3 с), вперемешку. Разметка «закончена / нет» берётся из сценария; фразы выдуманные, без имён.
   - Та же запись нужна для настройки SpeechKit STT («Кора» → «хара/кара», разрывы длинных фраз).
2. **Модуль `src/audio/smart_turn.js`.**
   - `whisperLogMel(pcm16k)` на чистом JS; `createSmartTurn({ modelPath, threads: 1 })` → `predict(pcm16k) → { p, ms }`; `onnxruntime-node` лениво, в `optionalDependencies`; без пакета или файла — `available: false` и одна строка `turn.smart_off` в логе.
   - `tools/fetch_models.js` скачивает веса в `models/` (в `.gitignore`) и сверяет sha256 из `config/settings.json`.
   - Тесты: признаки сверяются с эталоном, посчитанным один раз питоновским `WhisperFeatureExtractor` на синтетическом сигнале (синус и шум); сессия ONNX — фейк. Плюс золотой тест на выходе: `p` нашей обвязки против питоновского `inference.py` на клипе короче 8 с (локально у владельца, с моделью).
   - Факты модели сверить по коду, а не по README: **с какой стороны добавляются нули** (в `inference.py`, `train.py` и в pipecat это может различаться — это критично), точный номер версии; закрепить commit репозитория и sha256 весов.
   - Инференс — в `worker_threads`: 10–100 мс на главном потоке задерживают звук.
   - Буфер фразы на слоте сбрасывается по финалу и по паузе: слот Телемоста переключается между людьми. На её собственном эхе модель не гоняем.
   - «Тихий чанк» — по адаптивному порогу (шумовой пол, как в `floor`/`vad.js`), а не по фиксированной энергии: на домашнем фоне фиксированный порог не срабатывает.
3. **Оценка на записи — `tools/smart_turn_eval.js`.** По каждой фразе из шага 1: `p`, время инференса, точность по порогам 0,3–0,8; доля фраз, где промежуточная гипотеза на тихом чанке совпадает с финалом; выигрыш по времени — до момента, когда **текст пригоден** (гипотеза совпала с финалом), а не до `p ≥ T`. Кроме сыгранных по бумажке фраз — реальные фразы из записи тест-комнаты (с согласия) со слабой разметкой: тот же слот продолжил речь ≤ 1,5 с → фраза незаконченная. Критерии: на законченных `p ≥ T` ≥ 90%, на оборванных `p < T` ≥ 80%, совпадение гипотезы с финалом ≥ 80%, медиана выигрыша ≥ 400 мс. Не проходит — модель остаётся только подсказкой агенту, без раннего пробуждения.
4. **Уши: `turn_hint`** под флагом `voice.smart_turn.enabled` (по умолчанию выкл.). Тесты на фейковом gRPC-клиенте, как в `yandex_cascade.test.js`: подсказка на тихом чанке, повтор после нового звука, пустая гипотеза.
5. **Политика пробуждения в хосте-агенте** — шаг 9 [agent_plan.md](agent_plan.md), **после живого теста агента**: Smart Turn — оптимизация задержки, а разваливался разговор. Тесты на фейковой модели и фейковом агенте.
6. **Живой тест с владельцем — только по его «го».** Сравнение с прогоном без флага по логу: время от конца речи до первого звука, число отменённых ранних решений, были ли «всё?» посреди рассказа.

## Открытые вопросы

- Точность и выигрыш на живых голосах через кодек Телемоста — шаг 3 на записи владельца; голоса коллег — только с их согласия.
- Нужен ли свой VAD (Silero) или хватает тихого чанка страницы. Начинаем с тихого чанка, Silero добавляем только если замеры покажут ложные срабатывания на фоне.
