# Smart Turn v3 в ушах каскада: план (27.09.2026)

Цель — сократить задержку ответа (~2,2 с, TODO в CLAUDE.md) и отличать «человек закончил» от «человек задумался посреди фразы». Обзор, откуда взялась модель, — в [opensource_group_voice.md](opensource_group_voice.md).

## Модель

[pipecat-ai/smart-turn](https://github.com/pipecat-ai/smart-turn), версия 3.2, лицензия BSD-2-Clause.

- Смотрит на **звук**, а не на текст: интонацию, темп, обрыв слова.
- Выдаёт вероятность того, что реплика закончена; порог в примере — 0,5.
- Внутри Whisper Tiny + линейный классификатор, ~8 млн параметров. 23 языка, русский есть.
- Два файла ONNX: int8 для CPU на 8 МБ и fp32 для GPU на 32 МБ. На CPU 10–100 мс.
- Вход — последние ≤8 с текущей реплики, 16 кГц моно. Если звука меньше 8 с, нули добавляются **в начало**. Запускать её надо, когда VAD увидел тишину; если человек заговорил снова, прогнать заново по всей реплике.

### Нужно ли что-то разворачивать

Нет, сервер и GPU не нужны. Модель работает в нашем Node-процессе на CPU ноутбука:

- **Рантайм** — npm-пакет `onnxruntime-node` с готовыми бинарниками для macOS, Linux и Windows.
- **Веса** — один файл на 8 МБ. В git не кладём: скрипт скачивает его в `models/` (в `.gitignore`) и сверяет sha256.
- **Признаки** — log-mel как у `WhisperFeatureExtractor(chunk_length=8)` из `inference.py` репозитория. Это около 100 строк JS:
  - обрезка или дополнение нулями слева до 128 000 отсчётов;
  - нормировка к нулевому среднему и единичной дисперсии (`do_normalize=True`);
  - STFT с n_fft 400, hop 160 и окном Ханна;
  - 80 мел-фильтров Slaney;
  - `log10`, ограничение снизу на уровне `max - 8`, затем `(x + 4) / 4`.

  На выходе тензор `input_features` [1, 80, 800]. `@huggingface/transformers` ради этого не тянем: он тащит `sharp` и лишний рантайм.

Остальное из обзора разворачивать не нужно или не стоит:

- LiveKit turn-detector тоже локальный (281 МБ), но с лицензией под LiveKit;
- When2Speak — это данные, а не сервис;
- SAA — только облако.

## Как применяем

### Применение A — раньше закрывать фразу (главное)

В `yandex_ears.js` у каждой сессии слота есть PCM текущей фразы. На **первом тихом чанке** слота, примерно через 100 мс после конца речи, модель прогоняется по последним 8 с фразы. Энергия чанка считается в Node по той же мере, что в ворклете: среднее |x| по каждому 8-му отсчёту больше 80.

- `p ≥ порог` → `end(s, 'smart_turn')`: закрываем поток сессии, не дожидаясь нулевого хвоста. SpeechKit отдаёт финал, когда поток закрыт (замер 26.09: «the final only came when the stream closed»). Следующая фраза этого слота откроет новую сессию: так уже работает `pushAudio`.
- `p < порог` → ничего не меняем: хвост нулей и EOU SpeechKit работают как сейчас.
- Пока модель не отработала, звук продолжает уходить в SpeechKit. Если человек заговорил снова, решение отменяется, а следующий прогон идёт по всей фразе.

Ожидаемый выигрыш — оценка, её надо проверить: финал через ~0,2 с + время финала после закрытия потока вместо ~0,9 с. Если финал после закрытия приходит быстрее 300 мс, ответ ускоряется на ~0,4–0,6 с, до ~1,6–1,8 с.

Риск — ложное «закончил» посреди фразы. Тогда одна реплика человека придёт двумя финалами, и мозг может ответить на полвопроса. Защиты:

- порог настраиваем на записях (шаг 1). Для раннего закрытия, скорее всего, понадобится выше 0,5;
- ранний финал помечаем полем `early: true`. Если тот же слот заговорил снова в течение ~1 с, `host.js` склеивает строки транскрипта. Решение мозга по первой половине должно стать устаревшим: продолжение сдвигает `stateVersion` (механизм `stale` в `host.js` уже есть, но `stateVersion` сейчас двигают только смены хода, а проверяет его только `give_word`). Если она уже заговорила, её перебьёт распознанная речь продолжения (`interruptsHost`);
- без частичной гипотезы SpeechKit (текст пустой) раньше не закрываем.

### Применение B — не перебивать задумавшегося (раунд)

По каждой фразе уши шлют событие `turn_hint {track_id, p, t}`. `floor.js` учитывает последнюю подсказку текущего спикера:

- `p < 0,3` (фраза явно оборвана: «и ещё я…») → `check_done_ms` растёт с 2500 до ~4000 мс;
- высокая `p` без фразы-закрывателя ничего не меняет: «всё?» по-прежнему по тишине, раньше не спрашиваем.

Правка маленькая, и её проще проверить живьём: пункт 4 списка «ждёт теста с владельцем» в CLAUDE.md.

### Что не делаем

- Не трогаем `floor.silence_ms` = 700 мс после финала: он прячется за временем мозга, а данных, что его можно снижать, нет.
- Не используем модель для перебивания Коры. Там решает распознанная речь (`interruptsHost`), и это работает.

## Шаги

Каждый шаг — отдельный коммит с тестами, `npm test` остаётся герметичным.

1. **Замер без комнаты — `tools/smart_turn_probe.js`.** Люди и код хоста не нужны, стоит копейки.
   - SpeechKit TTS рендерит ~20 русских реплик двух типов:
     - законченные: «у меня всё», «вчера закрыл два бага, сегодня на ревью»;
     - оборванные на полуслове или союзе: «сегодня я доделываю интеграцию с…», «вчера я занимался, э-э…».

     Тексты выдуманные, без имён.
   - По каждой реплике инструмент печатает `p`, время инференса и точность по порогам 0,5 / 0,6 / 0,7.
   - Те же рендеры идут через `createYandexEars` двумя способами: с нулевым хвостом, как сейчас, и с закрытием потока сразу после речи. Печатается время до финала по каждому способу. **Это главный вопрос плана.**
   - Критерии, чтобы идти дальше: на законченных `p ≥ 0,5` ≥ 90%; на оборванных `p < 0,5` ≥ 80%; финал после закрытия потока ≤ 300 мс (p50).

   Если финал после закрытия приходит медленно, применение A сводится к запуску мозга по последней частичной гипотезе. Это отдельный разговор.
2. **Модуль `src/audio/smart_turn.js`.**
   - `whisperLogMel(pcm16k)` на чистом JS.
   - `createSmartTurn({ modelPath, threads: 1 })` → `predict(pcm16k) → { p, ms }`. `onnxruntime-node` подгружается лениво.
   - `onnxruntime-node` — в `optionalDependencies`. Если нет пакета или файла модели, модуль говорит `available: false` и в лог уходит одна строка `turn.smart_off`.
   - `tools/fetch_models.js` скачивает файл и сверяет sha256 из `config/settings.json`.
   - Тесты:
     - признаки сверяются с эталоном, который один раз посчитан питоновским `WhisperFeatureExtractor` на синтетическом сигнале (синус и шум, без голосов);
     - сессия ONNX подменяется фейком, модель и пакет тестам не нужны.
3. **Уши, применение A**, под флагом `voice.smart_turn.enabled` (по умолчанию `false`).
   - Кольцевой буфер фразы по слоту (≤8 с, 16 кГц) — там уже есть ресэмпл 24→16 кГц.
   - Прогон модели на первом тихом чанке, закрытие потока по порогу `voice.smart_turn.finalize_p`, поле `early` в `stt_final`.
   - Событие лога `turn.smart {track, p, ms, audio_ms, decision}`.
   - Тесты — на фейковом клиенте gRPC, как в `yandex_cascade.test.js`: закрытие по высокой `p`, без закрытия при низкой, отмена при новом звуке, пустая гипотеза.
4. **Хост:**
   - склейка раннего финала с продолжением;
   - `bump()` на продолжении, чтобы решение по первой половине пришло как `stale`;
   - `answer` и `speak` с `stale` после раннего финала не звучат.

   Тесты в `core_host.test.js`.
5. **Floor, применение B:** `turn_hint` → продление `check_done_ms`. Тесты в `core_floor.test.js`.
6. **Одиночный прогон в тест-комнате без людей:** вход, модель загрузилась, в логе нет ошибок, `turn.smart` пишется на её собственном эхе.
7. **Живой тест с владельцем — только по его «го».** Сначала сообщение из трёх частей: что изменено, что проверяем, какие фразы он говорит. Сравнение с прогоном без флага по логу:
   - `stt_ms` в событиях `transcript`;
   - время от `transcript` до `speech.start` для ответов на «Кора, …»;
   - число склеек ранних финалов;
   - были ли вопросы «всё?» посреди рассказа.

## Открытые вопросы

- Как быстро SpeechKit отдаёт финал после закрытия потока: от этого зависит, есть ли выигрыш вообще. Шаг 1.
- Точность модели на русском после кодека Телемоста. TTS-рендеры в шаге 1 кодек не проходят. Для оценки на живых голосах понадобится локальная запись слотов в `_internal/`, которая уже в `.gitignore`. Её можно включить только с согласия владельца: это разговоры команды.
- Нужен ли свой VAD (Silero) или хватает тихого чанка страницы. Начинаем с тихого чанка, Silero добавляем только если замеры покажут ложные срабатывания на фоне.
