# Эксплуатация Коры (WP9)

Памятка: как запустить, как остановить, где логи, как потом включить планировщик.

| Файл | Что делает |
|---|---|
| `run-standup.ps1` | обёртка запуска: один экземпляр, снимает старый `state\STOP`, пишет лог в `%USERPROFILE%\sync\logs`, сторож, алерт в Telegram при сбое |
| `stop-standup.ps1` | kill switch файлом `state\STOP`; с `-Kill` ещё и завершает процессы |
| `register-task.ps1` | задача планировщика `StandupHostKora` (пн–чт 09:55), только с OK Сергея |
| `src/ops/telegram.js` | DM Сергею: `sendAlert`, `sendSummary`, CLI для обёртки |
| `src/ops/stopflag.js` | `watchStopFlag`, `clearStopFlag`, `isStopRequested`, `requestStop` |

## Понедельник 21.09: ручной запуск

Нужно видимое окно PowerShell 7 (`pwsh`, например вкладка Windows Terminal).

```powershell
cd C:\Users\aleks\template\scripts\standup_host
npm run check                 # 09:50: последняя строка "RESULT OK"
.\run-standup.ps1 --verbose   # 09:55
```

- Бот заходит в `times.join` (09:58) и сам выходит после стендапа (не позже 10:35).
- Окно называется «Кора: стендап (Ctrl+C = стоп)». Держите его открытым до выхода Коры: закрытие окна крестиком тоже убивает бота, только без аккуратного выхода.
- Запасной режим (заходит, слушает, пишет лог, молчит): `.\run-standup.ps1 --shadow --verbose`.
- Тестовый прогон без алертов: `.\run-standup.ps1 -NoAlert --url <тест-комната> --at 09:58 --day mon --verbose`.

Всё, кроме ключей обёртки, уходит в `node src\main.js` как есть (`--at`, `--day`, `--shadow`, `--url`, `--verbose`, `--no-brain`, `--check`). Ключи обёртки пишутся с одним дефисом:

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `-Scheduled` | нет | запуск планировщиком: хост стартует только пн–чт в окне `-NotBefore`…`-NotAfter` МСК |
| `-NotBefore HH:MM` | 09:30 | раньше плановый запуск пропускается (например, догнавший вчерашний) |
| `-NotAfter HH:MM` | 10:10 | позже плановый запуск и перезапуски пропускаются |
| `-MaxMinutes N`, `-HardStop HH:MM` | 50, 10:45 | сторож: когда прошло N минут **и** наступило HardStop МСК, ставит `state\STOP`, ждёт 20 с, потом завершает node и Chrome. `-MaxMinutes 0` выключает |
| `-NoAlert` | нет | не слать DM (тесты) |

## Как остановить

| Способ | Что происходит | Когда |
|---|---|---|
| Голосом «Кора, стоп» | прерывает реплику и молчит, оставаясь в звонке; вернётся к ведению по обращению по имени | в звонке |
| Голосом «Кора, уйди из встречи» | выходит из звонка за ~1–2 с, процесс завершается | в звонке |
| `.\stop-standup.ps1` | то же через файл `state\STOP` | из любого окна, в том числе при скрытом запуске |
| `.\stop-standup.ps1 -Kill` | флаг, а если хост не вышел за 10 с, завершает node вместе с Chrome | хост завис, или запуск скрытый и Ctrl+C некуда нажать |
| Ctrl+C в окне обёртки | Ctrl+C получает и хост: выходит из звонка. Обёртка ждёт его до 10 с (лог дописывается), потом завершает процессы | ручной запуск |

- Флаг `state\STOP` действует только на текущий запуск: следующий `run-standup.ps1` его снимает и пишет об этом в лог. Пропустить плановый день: `Disable-ScheduledTask StandupHostKora` (см. ниже).
- «Завершить» задачу в самом планировщике убивает только pwsh, node может остаться. Используйте `stop-standup.ps1 -Kill`.
- `stop-standup.ps1` работает и в Windows PowerShell 5.1.
- Реакцию хоста на флаг и на голосовую команду подключает WP6 (`watchStopFlag`, см. последний раздел).

## Логи

| Что | Где | Внутри |
|---|---|---|
| События хоста | `scripts\standup_host\logs\standup_YYYY-MM-DD.jsonl` | всё, включая транскрипт |
| Вывод обёртки и хоста | `%USERPROFILE%\sync\logs\standup_YYYY-MM-DD.txt` | строки обёртки `[run-standup]` и stdout/stderr хоста с временем МСК, UTF-8; несколько запусков за день дописываются в один файл |

Следить в реальном времени: `Get-Content "$env:USERPROFILE\sync\logs\standup_$(Get-Date -Format yyyy-MM-dd).txt" -Wait -Encoding utf8`.

`daily-sync.ps1` удаляет из `sync\logs` файлы старше 30 дней. Папку `logs\` с JSONL он не чистит, но зеркалит на хаб вместе со всей папкой `template`.

## Алерты в Telegram

- Кому: личка Сергея (`settings.telegram.alert_chat_id` = 111111111) от бота `TELEGRAM_BOT_TOKEN`. Проверено 18.09: доставляется.
- Формат: `Кора: <текст>`, для warn/error впереди `[WARN] ` / `[ERROR] `.
- Обёртка шлёт `[ERROR]`, когда хост завершился с кодом не 0 (кроме 64 и Ctrl+C), когда сторож остановил хост и когда хост не стартовал. `[WARN]` приходит, когда плановый запуск в пн–чт пришёл позже 10:10 (компьютер спал). С `--check`, `--help` и `-NoAlert` алертов нет.
- В алерте только код выхода, строка `fatal:` и путь к логу. Транскрипт в Telegram не уходит.
- Доставка: до 3 попыток (паузы 5 и 10 с), 10 с на попытку, на 429 ждёт `retry_after` (до 30 с); 400/401/403/404 не повторяет. Худший случай около 45 с.
- Вручную: `node src\ops\telegram.js --dry-run "текст"` показывает сообщение и чат, ничего не отправляя; `node src\ops\telegram.js --level warn "текст"` отправляет. Коды: 0 доставлено, 1 нет, 64 неверные аргументы.
- Ошибка `HTTP 403: Forbidden: bot can't initiate conversation with a user` значит, что Сергею нужно открыть бота и нажать /start. `HTTP 401` значит, что неверный токен.

## Коды выхода `run-standup.ps1`

| Код | Значение |
|---|---|
| 0 | хост завершился штатно, или плановый запуск пропущен (не пн–чт, вне окна 09:30–10:10) |
| N | иначе код хоста как есть: 1 ошибка или не готов, 2 хост ещё не подключён (до WP6), 64 неверные флаги |
| 20 | хост не запустить (нет `node.exe` или `src\main.js`, ошибка старта) или сбой самой обёртки |
| 21 | сторож остановил хост |
| 22 | Кора уже запущена: второй экземпляр не стартует (mutex и поиск процесса `node …\src\main.js`) |
| 64 | неверные ключи обёртки |
| 130 | хост вышел по Ctrl+C. Если Ctrl+C прервал саму обёртку, код ставит pwsh |

В планировщике код виден как «Результат последнего запуска» (`LastTaskResult`).

## Планировщик: со вторника и только с OK Сергея

Регистрация меняет систему надолго, поэтому `register-task.ps1` пока не запускался: проверены синтаксис (pwsh 7 и 5.1) и сборка объектов задачи в памяти.

```powershell
.\register-task.ps1 -WhatIf                  # показать задачу, ничего не менять
.\register-task.ps1                          # зарегистрировать (повторный запуск заменяет)
.\register-task.ps1 -HostArgs '--shadow'     # первые дни: заходит и молчит
Get-ScheduledTask StandupHostKora | Get-ScheduledTaskInfo   # LastRunTime, LastTaskResult, NextRunTime
Disable-ScheduledTask StandupHostKora        # пропустить дни (отпуск, праздник); вернуть: Enable-ScheduledTask
.\register-task.ps1 -Unregister              # удалить
```

Что внутри задачи:
- пн–чт 09:55 МСК; время записано с `+03:00`, поэтому смена часового пояса ноутбука его не сдвигает;
- текущий пользователь, только когда он вошёл в систему (пароль не сохраняется, Chrome есть где открыть окно);
- StartWhenAvailable: пропущенный запуск догоняется, а окно 09:30–10:10 держит сама обёртка (`-Scheduled`). Позже 10:10 ничего не стартует, в пн–чт об этом приходит `[WARN]`;
- действие `pwsh -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File run-standup.ps1 -Scheduled [HostArgs]`, рабочая папка `scripts\standup_host`;
- один экземпляр (IgnoreNew), на батарее тоже, приоритет Normal (по умолчанию задачи идут с Below Normal, node и Chrome его наследуют, а это звук в реальном времени), лимит 2 ч (сторож обёртки в 10:45 срабатывает раньше), перезапуск при сбое запуска 2 раза через 1 мин.

До регистрации стоит проверить спайк S9 (headful Chrome из скрытого pwsh) той же командной строкой, но без планировщика и в тест-комнате:
`pwsh -NoProfile -WindowStyle Hidden -File .\run-standup.ps1 -NoAlert --url <тест-комната> --at 09:58 --day tue`.

## Для WP6: как хост подключает ops

- Старт: `clearStopFlag()` (обёртка уже сняла флаг, но хост могут запустить и напрямую), затем `watchStopFlag(() => выйти из встречи)`. Опрос раз в 250 мс: до выхода проходит ~1–2 с (обрыв реплики + `telemost.leave`). Голосовая команда может вызвать `requestStop('voice')`, чтобы остановка пережила перезапуск.
- Сбои (упал браузер, не удалось войти): `sendAlert(text, {level: 'error', log})` без `await` на критическом пути. Функция не бросает исключений, событие `telegram.send` пишется в JSONL.
- Ctrl+C: обёртка ждёт выхода хоста 10 с, потом завершает дерево процессов. Выход из звонка по SIGINT должен укладываться в это время.
- Поздний старт: StartWhenAvailable и перезапуски планировщика могут поднять хост в любой момент до 10:10, когда стендап уже идёт.
- Код выхода 0 означает штатное завершение; любой другой (кроме 64 и 130) обёртка превращает в DM.
