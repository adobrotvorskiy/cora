## Конец реплики (после теста 18.09)

Реплика заканчивается **только** так:
1. явный closer в транскрипте («у меня всё», «как-то так», «передаю», «на этом всё», «всё, спасибо») + 700 мс тишины по энергии;
2. цикл «всё?»: тишина ≥ `check_done_ms` (2,5 с) → клип `check_done` («Тима, всё?») → «да / всё / угу / так точно» (или closer) → конец; «нет / подожди / ещё» → продолжаем; тишина 4 с после вопроса → конец;
3. никто не заговорил 6 с после передачи слова → `are_you_here` → `skipped`, слово дальше (в конце `return_to_skipped`);
4. спикер вышел из звонка; жёсткий дедлайн 10:30.

Стоп VAD (семантический или энергетический) — сигнал, не решение: он никогда не заканчивает реплику (в тесте пауза 0,6 с внутри апдейта закрыла круг).

Подтверждённый конец исполняется как **ack → handoff**: клип активного слушателя (`ack` «Спасибо, Серёжа!», `ack_short` «Принято!» для реплик короче 6 с, `ack_blocker` если в тексте реплики был блокер/риск/проблема) → пауза 150 мс → `handoff_plain` («Дальше Тима.») следующему по плану, или `open_floor`, если план пуст. Варианты ротирует `ClipStore` (один и тот же не подряд). Никаких пересказов и итогов: их не пишет ни код, ни мозг (`engagement.ack` выключает реплики слушателя; `engagement.clarify_blockers` зарезервирован, выключен).

**Ложный конец.** Любой barge-in во время ack / handoff / `open_floor` / «всё?» / прощания означает, что человек не закончил: фаза и спикер восстанавливаются, очередь реплик очищается, извинения поверх человека нет (`turn.end_reverted`). Переходы состояния (`finishTurn`, `beginTurn`, `open_floor_asked`) делаются только **после** полного проигрывания клипа.

**Open floor → прощание:** ≥ 6 с тишины после вопроса «кто хочет добавить?» и никакой речи. Если кто-то заговорил после вопроса — решает мозг (`silence` → `leave`/`answer`), в скриптовом режиме ждём 12 с тишины. Прощание прерываемо, как всё: barge-in на нём → назад в open floor (`round.closing_reverted`), выход только после подтверждения (мозг `leave`, снова тишина, дедлайн 10:35 или `--max-minutes`).

## Цикл событий

Все обработчики идут через `Serializer` (по одному), речь — фоновая задача, чей конец снова входит в сериализатор. Поэтому barge-in обрабатывается, пока Кора говорит. Стоп (`state/STOP`, «Кора, уйди из встречи») идёт в обход сериализатора: обрыв реплики и выход из звонка сразу, не в очереди за другими обработчиками.

Входы: `installObservers` (участники, active speaker → в floor уходят только id других участников) + опрос плиток раз в 3 с; `__host_audio` (100 мс PCM + уровни) → floor/attribution/ears; события ушей (`vad`, `stt_delta`, `stt_final` — тексты проходят `config/stt_fixes.json`: PRX → PRJX, Кара → Кора…); события страницы (все → `player.onPageEvent`; `worklet.error` фатально; все удалённые треки закончились → `ears.flush()`); события floor; тик 50 мс (таймеры, предложение старта, open floor, `--max-minutes`).

### Что решает код, что мозг

| Событие | Код (всегда) | Мозг (если включён) |
|---|---|---|
| 10:00 `start` | `--no-brain`: Орлов есть → старт-клип ему; нет → приветствие + просьба пингануть | `timer` → обычно `give_word` Орлову (старт-клип) или `speak` |
| 10:02 `wait_lead_until` | без брейна: предложить стартовать без него; 6 с тишины = согласие → первому по ростеру | `timer`; если мозг молчит 45 с после срока — предлагает код |
| подключился / вышел | Орлов в раунде → первым в план; поздний → в конец; ушёл текущий → следующий | `joined/left` только до старта раунда |
| конец реплики (см. выше) | ack → handoff (`plan.next`) без мозга; план пуст → open floor | `plan_refresh` через 15 с после начала монолога: берётся только `plan` |
| тишина 2,5 с | клип `check_done` | — |
| barge-in | abort + flush ≤ 300 мс; на ack/handoff/open floor/прощании → ложный конец, откат; 2 подряд → бэкофф 3 с; после любого — 1,5 с тишины перед следующей репликой | `barge_in` только для ответов/свободных реплик, сыгранных < 30 % |
| вопрос к ведущей | по имени («Кора/Кара/Cora/ведущая»); без имени: в комнате ≤ 2 человек — любой вопрос её; в группе — «ты/тебя» в 8 с после её реплики или вопрос про ИИ/бота | `question_to_host` (high) → `answer`; слово остаётся у прежнего спикера; повтор того же ответа в 10 с и `answer` без открытого вопроса отбрасываются |
| «Кора, стоп» | abort реплики; дальше молчит и слушает, таймеры подавлены; возврат по обращению по имени | — |
| «Кора, уйди из встречи» / `state/STOP` | abort реплики и выход из звонка за ~1–2 с, процесс завершается | — |
| 10:28 | `wrap_up_soon` перед следующим handoff | `timer` вне раунда |
| 10:30 | после подтверждённого конца текущей реплики → прощание; в open floor → сразу | — |
| 10:35 | выход без фраз | — |
| `--max-minutes N` | прощание и выход; ещё через минуту — выход в любом случае | — |

Действия мозга (`applyAction`): `plan` применяется всегда (с валидацией присутствия); `give_word` до старта = старт раунда (лид, если он в комнате, идёт первым); в раунде при активной реплике или идущем конце реплики → `to` первым в плане (не перебиваем); `speak`/`answer` пока играет другой ответ → отбрасываются (кроме нового вопроса); `leave` при незаконченном круге игнорируется (кроме дедлайна); `post_chat` недоступен гостю.

## Речь

`say(spec, after)` ставит реплику в очередь (≤ 4). `speakOne`: клип из `ClipStore.get(key, {person, present})` (для гостей — объект с именем из Телемоста), промах → живой verbatim `player.playLive(mouth, text)`; текст мозга, совпадающий с фразой из `phrases.json`, тоже идёт из кэша. Ждёт `floor.canSpeak` до `maxWaitMs` (8 с, старт/финал 15–20 с), иначе `speech.skipped room_active` (handoff тогда откладывается, слово остаётся у говорящего). В shadow — `speech.shadow` с текстом и переход состояния «как будто сказано». Логи хоста: `speech.start/end/abort/shadow/skipped/dropped/error/barge_in` (плеер WP4 запущен с `logSpeech:false`).

## Флаги (`src/main.js`)

`--url`, `--at HH:MM[:SS]`, `--day`, `--shadow`, `--verbose`, `--no-brain`, `--live`, `--max-minutes N`, `--no-alert`. `--live` обязателен для боевой комнаты; тесты — только `--url <тест-комната>` или `tools/run_testroom.js`. `--check` требует ключ провайдера голоса (`Cora_KEY` для openrouter), не OpenAI.

## Настройки (новые ключи, все необязательны)

- `floor`: `silence_ms 700`, `check_done_ms 2500`, `barge_in_ms 200`, `barge_in_backoff_ms 3000`, `post_barge_in_silence_ms 1500`, `energy_db null` (фиксированный порог; null = адаптивный), `energy_above_floor_db 12`, `energy_db_min -62`, `floor_window_ms 5000`, `closer_handoff_ms 700`, `are_you_here_ms 6000`, `check_done_answer_silence_ms 4000`.
- `engagement`: `ack true`, `clarify_blockers false`.
- `guards`: `max_brain_calls 400`, `max_brain_cost_usd 1.5`, `max_live_readouts 60`.
- `browser.hide_incoming_video` (выкл.), `browser.wait_admission_ms`; `avatar.mode: "segments"` + `avatar.video`; `cost.usd_rub`.
- `config/stt_fixes.json`: канон → варианты распознавания (целые слова, без регистра).
