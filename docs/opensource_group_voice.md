# Опенсорс для голосового бота в групповом звонке (обзор 27.09.2026)

Что есть в открытом доступе для бота, который участвует в разговоре нескольких людей, и что из этого пригодится Коре. Итог: готового опенсорс-решения «ИИ-ведущий группового звонка» нет. Есть три слоя, из каждого можно взять отдельные куски:

- боты, которые заходят в звонок;
- фреймворки голосовых агентов;
- модели «когда говорить» и «кто к кому обращается».

План по самому полезному из найденного, Smart Turn v3, — в [smart_turn_plan.md](smart_turn_plan.md).

## 2. Фреймворки голосовых агентов

- **[Pipecat](https://github.com/pipecat-ai/pipecat)** (Daily) и **[LiveKit Agents](https://github.com/livekit/agents)** рассчитаны на разговор один на один.
  - LiveKit: голосовой ассистент слушает одного участника. [Issue про нескольких](https://github.com/livekit/agents/issues/391) открыт с 2024 года, обходной путь — по экземпляру на человека.
  - Pipecat: в [issue 3218](https://github.com/pipecat-ai/pipecat/issues/3218) со вторым участником в комнате LiveKit растёт задержка и бот отвечает на прошлый вопрос.
  - Их главная ценность — WebRTC-транспорт, а наш транспорт — Телемост через Chrome. Переезд ничего не даёт.
- **[Kyutai Unmute](https://github.com/kyutai-labs/unmute)** — каскад STT → текстовая LLM → TTS, задержка ниже секунды. Модели Kyutai STT английские и французские (`stt-1b-en_fr`, `stt-2.6b-en`), для нас годится только как пример устройства.
- **[AgoraAI](https://github.com/skgadi/agora-ai)** (статья в MDPI Applied Sciences, 2026) — несколько ИИ-персон и несколько людей в одной комнате, Node + Socket.IO. **[Agora](https://github.com/0xyg3n/Agora)** — голосовые комнаты на LiveKit + Silero VAD + faster-whisper + edge-tts, 4★. Оба проекта исследовательские, отдельной логики «когда говорить» нет.

## 4. Исследования: где ломаются голосовые агенты в группе

- **[MP-Bench](https://arxiv.org/abs/2609.13076)** (EMNLP 2026 Findings): агента помещают в разговор четырёх человек, 927 задач.
  - Голосовые агенты реального времени понимают разговор не больше чем на 33%.
  - Решить, говорить ли, если по имени не позвали, могут примерно на уровне случайного.
  - Текстовая модель с точными подписями спикеров задачи решает, то есть узкое место — определить по звуку, кто говорит.

  Это подтверждает решение 26.09: каскад, мозг получает транскрипт с полем `who`, а speech-to-speech модели (`yandex_rt`) — тупик.
- **[MSI-Bench](https://arxiv.org/abs/2609.24812)**: подписи спикеров в транскрипте поднимают открытые модели на 21–44 пункта. Слабее всего у моделей память о том, кто что сказал.
- **[Робот Furhat в разговоре с группой](https://www.frontiersin.org/journals/robotics-and-ai/articles/10.3389/frobt.2026.1766383/full)** (Frontiers in Robotics and AI, 2026):
  - LLM возвращает ответ вместе с адресатом, точность адресата в параллельных разговорах — 92,6%;
  - синтез стартует с первого законченного предложения из стрима LLM.

  Второе совпадает с нашим TODO: начинать синтез по закрытию поля `text`.
- [Обзор многосторонних диалоговых агентов](https://arxiv.org/pdf/2505.18845) и [бенчмарк распознавания адресата](https://arxiv.org/abs/2501.16643): явное обращение есть лишь примерно в 20% реплик, и GPT-4o определяет адресата едва лучше случайного. Правило «отвечать на обращение по имени, остальное — осторожно» остаётся правильным.

## 5. Что взять

1. **Smart Turn v3** — в уши каскада, чтобы быстрее закрывать фразу и не спрашивать «всё?» человека, который задумался. См. [smart_turn_plan.md](smart_turn_plan.md).
2. **Синтез по готовому полю `text`** — практику подтверждают и Pipecat (TTS по предложениям из стрима LLM), и Furhat.
3. **Пустой спикер вместо угадывания**, как у Vexa: если подсвечены двое и громкость не помогает выбрать. Мозгу лучше увидеть `who: ?`, чем чужое имя.
4. **When2Speak** — источник ситуаций «надо молчать» для бенчмарка мозга, если язык и лицензия позволяют.
