# Кора — ИИ-ведущая стендапа команды в Яндекс Телемосте

Node-процесс заходит в Телемост через Chrome (`playwright-core`), слушает комнату, решает, что сказать, и говорит в звонок. Устройство и запуск описаны в [README.md](README.md), исходный замысел и пакеты работ — в [PLAN.md](PLAN.md), ядро — в [docs/core.md](docs/core.md). Этот файл держит договорённости и контекст, которых нет в коде.

## Данные людей и компании — только локально

Репозиторий публичный. Имена, фамилии и роли сотрудников, название компании, клиенты, ссылки на комнаты, chat id и любые id аккаунтов в git не попадают — ни в код, ни в промпты, ни в тесты, ни в доки.
- Реальные данные лежат только на машине владельца, в `.gitignore`: `config/people.json` (ростер, `team_name`, `keywords` — компания и клиенты для распознавания), `config/persona.md`, `config/playbook.md`, `config/phrases.json`, `config/stt_fixes.json`, `config/settings.local.json` (ссылки `meeting_url` / `real_room_url` / `test_room_url`, `telegram.alert_chat_id`, `voice.eleven_agent_id`, `yandex.folder`).
- В репозитории — выдуманные замены `config/*.example.*` (команда «Acme»: Ярослав Орлов, Глеб Невский…). Код берёт реальный файл, если он есть, иначе пример (`contentPath` в `src/config.js`).
- Код и промпты не содержат имён: руководитель, коллеги в примерах, название команды подставляются из ростера (`{team}`, `{lead_full}`, `{lead_name}`, `{colleague}`).
- Тесты герметичны: `npm test` ставит `STANDUP_EXAMPLES_ONLY=1` и видит только примеры. Новые тесты пиши на выдуманной команде.
- Перед коммитом проверь, что в diff нет реальных данных. Если что-то нужно команде, но это данные — клади в локальный файл и добавляй поле в пример.

## Как работать с владельцем проекта

- **Живые тесты разговора — только с ним и только по его «го».** Сначала сообщение из трёх частей: что изменено, что проверяем, какие фразы он говорит (шаги). Бота в тест-комнату запускаешь после его согласия. Одиночные прогоны без людей (вход, голос, ошибки в логе) делай сам, не спрашивая. Синтетических гостей (`tools/room_guest.js`) для проверки поведения в разговоре не используй: результаты непонятны.
- Не сваливай проблемы на его окружение. Микрофон и динамик ноутбука работают: эхоподавление Телемоста убирает её голос. Если что-то не работает, чини бота.
- Отвечай по-русски, коротко, с фактами из лога.

## Решения

- **Весь конвейер на Яндексе — `voice.provider = "yandex_cascade"`** (решение владельца, 26.09.2026):
  - уши: SpeechKit STT v3 (gRPC), отдельная сессия на каждый аудиослот Телемоста;
  - мозг: Yandex AI Studio, модель `aliceai-llm-flash/latest`;
  - рот: SpeechKit TTS v3, голос `alena`, роль `good`, скорость 1.1.
  Мозг отвечает JSON-действием, в синтез уходит только поле `text`.
- **`yandex_rt` (Yandex Realtime) — тупиковая ветка, откат на него не предлагать.** Speech-to-speech модель зачитывала вызовы инструментов и JSON и звала отсутствующих. Каскад чиним, даже если он в чём-то хуже.
- ElevenLabs остаётся только запасным вариантом (`elevenlabs_agent` или `yandex.cascade_mouth: "elevenlabs"`).
- Каскад работает на хосте `src/core/host.js` (написан 18.09 под OpenRouter). `src/core/agent_host.js` обслуживает провайдеры-агенты (ElevenLabs, Yandex RT).
- Расписание необязательно. Без `--start` у неё нет часов: стендап открывает по «Кора, начинай». В `config/playbook.md` разделы «Старт» и «Время» есть в вариантах `[по расписанию]` и `[по требованию]`, в промпт попадает один.

## Проверенные факты (замеры 26.09.2026)

- **Телемост отдаёт звук комнаты через SFU-слоты, а не дорожку на человека.** На стендапе с 6 участниками было 2 аудиодорожки. Кто говорит, определяется по подсветке плитки (`rootStroke_*`) на интервале фразы, см. `attribution.speakerForTrack`. Если подсвечены двое, выбирается тот, чья подсветка совпадает с громкостью именно этого слота.
- С обновления Телемоста 21.09 звонок живёт в iframe `/private-join/…`. Все обращения к DOM звонка идут через `telemost.meetingFrame()`. Наблюдатель подсветки до 26.09 смотрел в главный документ и молчал; теперь он ставится в iframe.
- **SpeechKit STT:**
  - `silence_chunk` детектор конца фразы игнорирует;
  - нулевой PCM + EOU `HIGH` + `max_pause_between_words_hint_ms: 500` закрывают фразу через ~0,9 с;
  - страница шлёт дорожку слота только пока в ней звук, уши досылают 1,5 с нулей.
- **SpeechKit TTS:** REST `utteranceSynthesis` отдаёт фразу на ~4 с речи целиком за 150–300 мс, 24 кГц. Ударение ставится `+` перед гласной; U+0301 из `people.json` переводится в `+`. Тариф API v3 — за запрос, по 250 символов (0,1626 ₽ за единицу, по данным поиска на 26.09.2026; сайт Yandex Cloud из облачной сессии недоступен, при случае сверить). Переопределяется в `yandex.tts_pricing`.
- **Бенчмарк мозга** (реальный промпт, 5 ситуаций, `node tools/bench_brain.js --provider yandex`):

  | модель | верных решений | задержка p50 |
  |---|---|---|
  | aliceai-llm-flash | 5/5 | 1,2 с |
  | yandexgpt-5.1 | 4/5 | 1,4 с |
  | yandexgpt-lite | 2/5 | 1,7 с |
  | qwen3.6 | 4/5 | медленная |

- **Когда говорить** (живые тесты 26.09): громкость комнаты для каскада не годится. Домашний фон держал её молчащей, а энергия в первые 200 мс её реплики обрывала её. Поэтому в каскаде:
  - `floor.activity = 'speech'`: комната занята только от частичной гипотезы до финала распознанной фразы;
  - её собственное эхо (≥60% слов из её недавних реплик) не считается;
  - перебить её может только распознанная речь (2+ слова не из её реплики или «подожди/стоп»);
  - на обращение по имени она отвечает не позже чем через 2 с (`forceAfterMs`).
- Распознавание путает «Кора» с «корабль», «карат» и т.п. Исправления — в `config/stt_fixes.json`.
- **Тест 27.09** (тест-комната, один человек, по требованию, ветка `claude/intelligent-ride-b49vrq`):
  - от конца фразы до её голоса ~2 с: финал STT 0,1–0,8 с, мозг 1,1–1,2 с (TTFT ~0,6 с), синтез 0,1–0,2 с;
  - предзагрузка почти ничего не дала: при `why` первым и `plan: null` поле `text` закрывается за 2–20 мс до конца ответа мозга;
  - SpeechKit STT не ставит «?», вопросы узнаются только по вопросительному слову в начале фразы;
  - AI Studio не отдаёт стоимость и не кэширует промпт (~7k токенов на каждый вызов): `brain.cost_usd` в `cost.summary` равен 0;
  - фильтр эха сработал, атрибуция по подсветке — `dom`, `high`.
- **Тест 27.09, прогон 2** (двое в комнате, код без утренних правок): разговор разваливался.
  - прямые вопросы без имени («я тебе вопрос задал») до мозга не доходили;
  - мозг не видел своих реплик и повторял «Все высказались…» и «Привет, …»;
  - устаревшая реплика из очереди звучала после более свежего решения;
  - «всё?» звучало сразу после её ответа: таймер тишины считал её речь паузой говорящего;
  - к каждому ответу модель клеила «X, продолжай» (так учило правило 9 и пример в промпте) и выдумывала правила про себя;
  - после ухода всех она сказала ещё три реплики в пустую комнату;
  - распознавание: «Кора» слышится как «хара» или «кара», длинные фразы режутся на куски. Это отдельная задача: сначала записать звук, потом подбирать настройки на записи.

- **Тест 28.09, хост-агент** (`--host agent`, тест-комната, ~5 мин, владелец и гость не из `people.json`, по требованию):
  - скорость: решение агента p50 0,54 с (мозг был 1,1–1,2 с), от финала STT до начала её реплики ~0,7–0,8 с;
  - имя инструмента приходит вместе с концом ответа (в 67 из 68 решений `name_ms` = `done_ms`): промежуточные слова по раннему имени инструмента не получатся, но и нужны меньше;
  - на вызов ~3,1–3,6k входных токенов (локальные персона и плейбук), 70 вызовов за 5 мин;
  - провалы:
    - 33 передачи слова людям, которых нет на встрече: в промпте был весь ростер, а во входе только id, гость без имени;
    - одинаковый отказ повторялся до 25 раз подряд;
    - стендап открывала репликой `say` («…тебе слово»), круг не начинался;
    - «Кора, заканчивай встречу» отклонялось (`round_not_finished`);
    - повторяла «когда будешь готов — скажи, начну» три раза;
    - в паре отвечала на болтовню между двумя людьми.
  - Исправлено (живьём не проверено):
    - ростера в промпте нет; во входе `present` с именами (`name`, `lead`); `give_word` принимает только id присутствующих (`enum`, если сервер откажет — без него);
    - до круга нет `ask_done` и `open_floor`;
    - отказ приходит с `can` — кому можно дать слово; тот же отказ дважды — `agent.stuck`, без пробуждений по тишине до новой речи;
    - `leave` по просьбе по имени;
    - текст передачи не может называть другого человека (`text_names_someone_else`);
    - повтор — 70% слов из её реплики за 30 с;
    - в паре к ней — вопрос, «ты» или ответ на её реплику.

- **Тест 28.09, прогон 2** (правки прогона 1 включены: имена во входе, ~3k токенов на вызов): модель `aliceai-llm-flash` всё равно не держит правила инструментов.
  - Четыре раза открывала стендап репликой `say` и звала отсутствующего руководителя: его имя есть в персоне и плейбуке.
  - Через 1 с после передачи слова гостье, ещё до её первой фразы, открыла свободное слово.
  - Звала `ask_done` на каждую фразу 11 раз подряд. Отказ `too_early` помечал её `stuck`, и настоящее «всё?» через 2,5 с так и не прозвучало. Это ошибка кода, исправлена: отказы «ещё рано» `stuck` не ставят.
  - Один раз ответила текстом-отказом «Я не могу обсуждать эту тему».
  - На «всем пока, хорошего дня» не попрощалась.
  - Вывод владельца: код обрастает костылями из-за слабой модели. **Пробуем Gemini Flash через Gemini API с ключом Google AI Studio** (`agent.provider: "google"`). Сначала офлайн, на сценариях и реплее логов 28.09, затем в тест-комнате.

Хост отдаёт строку в `YandexMouth.prefetch()`, и её `say()` играет готовый звук без нового запроса к TTS. Решение по-прежнему берётся только из полного проверенного ответа. В логе: `speech.prefetch`, `brain.action.text_ms` (когда строка была готова), в `speech.end` — `ttfa_ms`, в статистике рта — `prefetch {started, used, unused, failed}`;

- Исправлено по тесту 27.09 (живьём ещё не проверено):
  - отсутствующие люди в `plan` мозга выбрасываются с предупреждением. Раньше это был повторный запрос (+1,4 с на старте) или потерянное решение;

В группе так нельзя: вопрос без имени после «кто хочет добавить?» обычно к коллегам. Там её вопросом считается обращение по имени, «ты» в течение 8 с после её реплики (теперь и когда вопросительное слово не первое: «а ты во сколько начнёшь») или вопрос про ИИ. Остальное мозг видит после 6 с тишины (`silence`) и решает сам;

## Запуск и окружение

- Node ≥ 24, `npm install`, Chrome (канал `chrome`). Юнит-тесты ключей не требуют: `npm test`.
- **Облачная сессия Claude Code** (claude.ai/code на этом репозитории): хук `.claude/hooks/session-start.sh` ставит Node 24 (в образе Node 22, на нём часть тестов отменяется) и зависимости. Ключей, профиля Chrome с входом в Телемост и живых людей в облаке нет, поэтому там пишем код и гоняем `npm test`. Живые прогоны делаются на машине владельца: он подтягивает ветку и запускает `run-standup.ps1` или `tools/run_testroom.js`. Egress облака не пускает на `yandex.cloud` / `aistudio.yandex.ru`.
- **Ключи — только в env, не в репозитории.** Локально они лежат в `.env.personal` / `.env.local` корня родительского репозитория `template` (см. `src/env.js`). В облаке задаются переменными окружения. Имена задаёт `settings.keys`:
  - `key` — API-ключ Yandex Cloud: SpeechKit STT/TTS и AI Studio. Ключу нужны роли `ai.speechkit-stt.user`, `ai.speechkit-tts.user`, `ai.languageModels.user` на каталоге;
  - `Elevenlabs_Cora_API` — ElevenLabs, запасной вариант;
  - `Cora_KEY` — OpenRouter, старый провайдер;
  - `TELEGRAM_BOT_TOKEN` — алерты.
- **Машинные настройки** — в `config/settings.local.json` (в `.gitignore`), например:
  ```json
  { "voice": { "provider": "yandex_cascade" }, "yandex": { "folder": "<id каталога Yandex Cloud, к которому привязан ключ>" } }
  ```
  Без этого файла по умолчанию провайдер `openrouter` из `config/settings.json`.
- **Пробы для перехода на агента** (27.09, запускает владелец, из облака Яндекс недоступен):
  - `node tools/probe_agent_tools.js` — умеет ли AI Studio вызывать инструменты для модели мозга (со стримом, несколько вызовов за раз, когда приходит имя инструмента). Людей не нужно;
  - `node tools/probe_speaker_meta.js --url <тест-комната> --minutes 3` — передаёт ли Телемост автора реплики: сигнальный канал (WebSocket и DataChannel, с сети и из страницы), SSRC/CSRC у аудиоприёмников, расширения RTP в SDP. Нужны двое, говорить по очереди по ~10 с. Лог: `logs/probe_speaker_*.jsonl`, в нём имена, он остаётся локально.
- **Запись звука по слотам** (шаг 2 плана, для настройки распознавания и Smart Turn; только тест-комната, в боевой `record.refused`). Владелец запускает в двух терминалах:
  - `node tools/run_testroom.js --provider yandex_cascade --record --shadow --no-brain --max-minutes 12`;
  - `node tools/record_turns.js` — фразы по одной (Enter): законченные, оборванные на «…», с паузой 2 с посередине. Разметка — `_internal/rec_script_*.json`.
  Запись: `_internal/rec_<время>/slot_*.wav` (24 кГц, паузы слота заполнены нулями по часам лога) и `index.json` (`t0` каждого слота). В логе — `stt.partial` и у `transcript` поля `t0`/`t1`. Запись с голосами остаётся локально.
- **Хост-агент** (шаг 3 плана, 27.09, живьём не проверен): `"voice": {"host": "agent"}` в `settings.local.json` или `node tools/run_testroom.js --provider yandex_cascade --host agent`. По умолчанию — старый автомат.
  - Что сказать, решает агент (`src/agent/conductor.js` + `src/agent/draft_agent.js`, AI Studio с инструментами). Автомат хоста (закрывашки, «всё?» по таймеру, тишина открытого слова, сценарный старт) выключен.
  - В коде остаются пропуск на реплику, эхо, перебивание, стоп-фразы, дедлайны, пустая комната и инварианты: отклонённый вызов пишется в `agent.rejected`, агент видит `rejected` при следующем пробуждении.
  - Пробуждения: финал фразы и лестница тишины (круг 1 / 2,5 / 6 с, открытое слово 2,5 / 6 с, потом раз в 10 с, до трёх раз). Новая реплика или уход человека обрывают запрос в полёте и выбрасывают её ждущие реплики (`agent.aborted`, `agent.dropped`). После двух обрывов подряд решение применяется, если в комнате тихо.
  - В группе от трёх человек `say` посреди круга проходит, только если к ней обратились: по имени, «ты» в течение 8 с после её реплики или вопрос про ИИ (`mayAnswer` в `src/core/addressing.js`). Непрошеная реплика — не чаще раза в 20 с.
  - По ревью 27.09 (Fable): зависший переход после перебивания откатывается сам через 0,6 с (`turn.end_reverted why: orphaned`). Ответ на обращение по имени не выбрасывается новой репликой, а при повторном решении обращение ещё засчитывается. «всё?» — только если говорящий уже что-то сказал (`not_started`). Кто молчал весь ход, передаётся без «Спасибо» и остаётся в очереди, со второго раза — выступил. Своё «Спасибо» + `give_word` не дают второго «Спасибо» клипом. Пока ждёт стартовая реплика, передача слова отклоняется (`start_pending`). Руководитель может сам попросить начать с другого. «Кора, стоп» снимается только обращением по имени (и в старом режиме).
  - Модель агента — `agent.provider`:
    - `yandex` (по умолчанию, Yandex AI Studio);
    - `google` — Gemini API, ключ Google AI Studio в env `GEMINI_API_KEY`. Имя переменной задаёт `keys.google`; модель — `agent.model` или `brain.google_model` (`gemini-3.6-flash`); эндпоинт OpenAI-совместимый (`generativelanguage.googleapis.com/v1beta/openai`); `reasoning_effort: "low"`, если модель не примет — без него;
    - `openrouter` — `agent.model` в виде slug OpenRouter, ключ `keys.openrouter`.
  - В инструментах: `run_testroom.js --agent-provider google [--agent-model <id>]`, `run_scenarios.js --provider google [--model <id>] [--effort low|none]`, `replay_log.js --provider google`.
  - Бюджет: `agent.budget` `{max_calls: 800, max_tokens: 4e6, max_rub}`. Тариф AI Studio для рублей (`agent.pricing`) не задан — сверить.
  - Лог: `agent.wake` (что она увидела), `agent.decision` (вызовы, `name_ms`, `done_ms`, токены), `agent.rejected`, `agent.dropped`, `agent.aborted`, в `cost.summary` — `agent`.
  - Промпт (шаг 5, `src/agent/skills.js`): персона, плейбук по фазам и база с инструментами. Разделы плейбука раскладываются по заголовкам: «Старт» — до старта, «Очередь», «Пока человек говорит» — круг, «Финал» — открытое слово, «Время» — круг и открытое слово. «Роль», «Вопросы к тебе», «Всегда» и незнакомые заголовки идут во все фазы. «Стоп-фразы» и «Как это ложится на действия» агенту не идут. На примерах выходит ≤ 3k токенов на запрос (было ~7k). Проверить локальный плейбук: `node tools/agent_prompt.js [--phase round]`.
  - В примере плейбука правило «вопросы без имени посреди апдейта — не к тебе» противоречило ответу на «я тебе вопрос задал». Теперь: к ней — имя или «ты» сразу после её реплики. **Локальный `config/playbook.md` поправить так же** (раздел «Вопросы к тебе»).
  - Сценарии против модели: `node tools/run_scenarios.js --prompt skills` (по умолчанию, на примерах) или `--prompt draft` (одна база) — сравнить.
- **Реплей логов** (шаг 4, запускает владелец: логи с именами лежат только у него):
  - `node tools/replay_log.js logs/<лог>.jsonl [--mode forced|free] [--from mm:ss --to mm:ss]` — прошлый прогон через агента. `forced`: реплики людей и её прежние реплики в их время, решения агента только записываются. `free`: её реплики заменяются репликами агента. Выводит пробуждения и вызовы, в конце — сводку (отклонённые по причинам, оборванные, непрошеные реплики, реплики в пустую комнату). Отчёт — `_internal/replay_*.json`. `--scripted` проверяет путь событий без сети;
  - `node tools/log_to_scenario.js logs/<лог>.jsonl --from mm:ss --to mm:ss --id <имя>` — черновик сценария на выдуманной команде (id и имена в текстах заменены, склонения тоже). `expect` / `ideal` пишутся руками. Перед коммитом черновик проверяется на реальные данные: короткие имена и слова из `keywords` автоматически не заменяются.
- **Сценарии разговора для агента** (`src/agent/scenarios.js`, выдуманная команда Acme): по мотивам прогонов 27.09 — события (реплики, тишина, вход/выход, её реплики, перебивание, хор) и допустимые решения (`say` / `give_word` / `ask_done` / `skip` / `leave`, запреты вроде «продолжай» и выдуманных правил). Против настоящей модели: `node tools/run_scenarios.js [--only id] [--rounds 2]`, отчёт в `_internal/`. Новый провал в живом тесте — новый сценарий, а не новая регулярка в хосте.
